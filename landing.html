01 / FOUNDATIONS

A consensus layer with three commitments.

Most chains pick one of these. EntropyChain insists on all three because none of them works as well in isolation: trustless randomness needs decentralized hashrate, decentralized hashrate needs CPU-friendly mining, and CPU-friendly mining needs a memory-hard hash.

Memory-hard PoW

Mining uses Argon2id, the PHC competition winner. ASIC and GPU acceleration give a much smaller advantage than against SHA-256 — the bottleneck becomes DRAM bandwidth, not silicon. A laptop can mine. That's the point.

Per-block entropy

Every block publishes a beacon r_i = H("entropy" ‖ block_hash). The block hash covers the proof of work, so no one knows a beacon until its block is solved, and anyone can recompute it from public data. The chain itself is a randomness beacon — no VDF, no oracle, no committee.

Native primitives

Transactions like nft_random_mint and lottery_draw consume the beacon directly. No smart contracts. No oracle integrations. The protocol enforces fair derivation; verification is a single hash recomputation.

02 / MECHANICS

How a single random NFT mint actually works.

The end-to-end path from block production to verifiable trait derivation on a minted NFT — every step is deterministic, every input is public.

  1. Miner solves a block

    The miner assembles a block and searches for an Argon2id proof-of-work solution. Until a valid nonce is found, the block's hash does not exist, not even for the miner.

  2. The block hash becomes the beacon

    Every node computes r_i = sha256d("entropy" || block_hash). Because the hash covers the PoW nonce, nobody could know r_i in advance. It is queryable at /rpc/entropy/{height}.

  3. User submits a random-mint transaction

    The user names a collection, token_id and recipient, but no source of randomness. If the mint lands in block H, its traits come from the beacon of block H + 1, which does not exist yet.

  4. Protocol derives the traits

    Once block H + 1 is mined: h = sha256(r_{H+1} || collection || token_id). Rarity, power, element, colour and legendary status are read from bytes of h. Anyone can recompute them.

  5. NFT exists with verifiable provenance

    The NFT records the block whose beacon revealed it. Anyone can verify nothing was cherry-picked: the beacon did not exist when the mint was signed.

03 / NATIVE PRIMITIVES

Two transaction types that could not exist on most chains.

Both fully on-chain. No oracles. No committees. No off-chain computation. Each is a single transaction type the protocol enforces directly.

NFT

nft_random_mint

Mint an NFT whose traits are revealed by the beacon of the block after the mint. No one, the minter included, can know or pick the traits in advance. Every property is reproducible from public data.

Input
collection, token_id, recipient
Output
NFT whose traits the next block reveals
Trust
none — reproducible by any party
LOTTERY

lottery_draw

Create a lottery with a future draw_height, optionally a window of up to 16 blocks. Tickets are bought until that block; the winner comes from the window's block beacons. Prize paid natively, no escrow contract.

Input
lottery_id, prize, ticket_price, draw_height, draw_blocks
Output
verifiable winner from future blocks' beacons
Trust
none — protocol enforces selection
